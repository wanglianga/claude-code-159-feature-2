# 邻里药箱 · 社区共享借用 / 效期提醒 / 邻里互助（演示）

一个纯前端演示应用：居民登记家中多余但**未拆封**的常备非处方耗材（退热贴、碘伏、纱布、创可贴、口罩、体温计电池等），
经社区志愿者审核发布后，邻居可按症状场景申请借用，支持自取 / 志愿者代送 / 邻居门口无接触交接，交接拍照确认，
并按约定归还或补充。效期临近、多人争抢、超时未取、配送延误、共享人撤回、包装破损与疑似不适反应均有对应处理流程。

**夜间多人同时申请同一盒退热贴**时，系统按**距离、紧急程度、是否有儿童、库存数量、志愿者配送能力**逐项评分给出分配建议：
分到的居民锁定库存交接；未分到的居民**求助记录保留**，可转入相邻小区互助、选择替代用品或收到就医提示；
社区端能看到每一次分配的逐项理由并答复居民质疑；志愿者可登记到货并按求助记录补发，社区据此复盘夜间真实短缺。

> **社区只做物品流转和风险提醒，不做诊断建议。**
> 处方药、拆封药品、冷链药品、过期/包装破损物品**一律不能进入共享**。共享物品不替代就医。

技术栈：Vue 3（`<script setup>`）+ TypeScript + Pinia + Vue Router + Vite + Vitest。
所有数据保存在浏览器 `localStorage`（键 `medkit-share-state-v2`），无后端依赖；底部“演示时钟”可快进，用于演示效期、超时与延误。

## 本地启动

### 方式一：Node 直接运行（开发）

```bash
npm install        # 如本机 npm 缓存权限异常，可加 --cache /tmp/npm-cache
npm run dev        # http://localhost:5173
```

### 方式二：Docker / Compose 一键启动（生产静态产物 + nginx）

```bash
docker compose up --build -d      # 构建并后台启动
# 打开 http://localhost:8080
docker compose logs -f medkit-web # 查看日志
docker compose down               # 停止
```

或仅用 Docker：

```bash
docker build -t community-medkit-share .
docker run --rm -p 8080:80 --name medkit community-medkit-share
```

其他命令：

```bash
npm run typecheck  # vue-tsc 严格类型检查
npm run test       # Vitest 单元/流程/页面冒烟测试（17 个）
npm run build      # 类型检查 + 生产构建（输出到 dist/）
npm run preview    # 预览构建产物
```

## 页面与角色视图

- **药箱大厅 `/hall`**：按四个急用场景筛选 + 关键词搜索；仅展示审核通过且在有效期内的物品；卡片显示来源、规格、效期、余量/候补人数、取用地点。夜间应急退热贴（i13）可查看昨夜的完整分配记录。
- **物品详情 `/items/:id`**：借用强制逐项勾选确认 **来源 / 效期 / 包装状态 / 适用限制**；申请表单新增**紧急程度、是否有儿童、儿童年龄、实测体温、距取用点距离**五项分配因子；
  多户（≥2）同时候补时展示**实时分配建议面板**（志愿者可一键执行）；已执行的轮次展示逐户评分、库存/运力快照、完整理由、未分到居民的求助记录与出路、质疑入口与社区答复；同页展示借用记录、风险反馈与完整时间线。
- **登记共享 `/register`**：填写品名、规格、有效期、存放条件、是否整盒未开封、可借数量、取用地点、适用场景；实时规则校验，禁入品提交即被拦截。
- **我的共享 `/my-shares`**：登记人物品状态与审核意见；确认/婉拒申请、发起交接、拍照确认、撤回。
- **我的借用 `/my-borrows`**：候补、取件/拍照确认、超时警告、归还/补充/赠予；**未分到物品时显示求助记录、三条出路（相邻小区互助 / 替代用品 / 就医提示）、质疑提交与社区答复、到货补发后的交接入口**。
- **志愿者工作台 `/volunteer`**：审核、配送拍照/报备延误/改派、超时催办与释放、候补递补；
  **候补协调页对“同一物品 ≥2 户同时申请”给出醒目入口并按建议执行分配；到货补发页按挂起的求助记录逐户补发，并可登记新到货**。
- **社区工作台 `/staff`**：风险看板、反馈处置、过期报废、60/30 天效期分级、双重复核、全链路追溯；
  **“分配理由与质疑”页可查看每一轮分配的逐户因子与理由全文并答复质疑；“夜间短缺复盘”页按物品聚合未满足需求（待补发/已补发/已关闭户数）**。
- **互助边界 `/guide`**：把“做什么/不做什么”、四类禁入、借用前四项确认、流程、七种异常与夜间争抢分配规则说清楚。

## 关键业务规则（可在 `src/rules.ts` 与 `src/stores/medkit.ts` 核验）

- **夜间多人争抢分配（`night-allocation-v1`）**：同一物品 ≥2 户同时候补且库存不足时启动。评分因子（全部可解释、逐户留痕）：
  1. **紧急程度**：儿童高热（≥39℃/精神差）50 分、正在发烧 32 分、低热观察 14 分、备货 0 分；
  2. **是否有儿童**：有儿童 +20 分；
  3. **距离**：≤200m +15 / ≤500m +10 / ≤1km +5 / 更远 0；
  4. **志愿者配送能力**：需要代送且今晚仍有在岗运力 +10（运力按“在岗志愿者总额度 − 已承担未完成配送单数”计算，优先给基础分高的申请）；
  5. **申请先后**：同分时按申请时间微调（最多 ±0.9 分），保证排序稳定。
  按总分从高到低、依库存**逐单整盒切分**；库存不足一单时跳过该单继续尝试后面的申请。
- **未分到居民的三条出路**：转入相邻小区互助（朝阳园门岗/滨河家园代收点代送）、选择替代用品（凉毛巾/温水擦拭等物理降温指引）、收到就医提示（儿童高热不退立即夜间急诊；该出路关闭求助）。
- **求助记录与补发**：未分到不等于诉求消失——申请取消但保留为求助记录（`helpStatus: open/fulfilled/closed`）；志愿者登记到货后按记录一键补发，申请重新进入锁定与交接流程。
- **理由留痕与质疑**：每轮分配保存库存与运力快照、逐户评分、理由全文（`AllocationRound.summary`）；居民可提交质疑，社区工作人员在工作台按逐项因子答复，问答同时写入物品时间线。
- **库存锁定**：普通申请初始“候补”，确认后锁定数量；取消或闭环后释放，候补按申请时间递补。
- **效期**：60 天黄色预警、30 天红色预警、过期大厅自动禁借并进入“待报废”清单。
- **取件时限 / 配送 SLA**：确认后 24 小时未交接标红；志愿者代送 6 小时未送达标红、可报备/改派。
- **撤回 / 反馈即隔离**：撤回取消全部候补、进行中借用继续履行；包装破损/疑似不适立即隔离并取消未完成申请，疑似不适明确引导停止使用并就医。
- **全链路串联**：分配建议、执行、出路选择、质疑、答复、到货补发均写入同一物品时间线（`allocation_suggested/allocation_adopted/aid_chosen/help_fulfilled/question/question_replied`）。

## 建议的手工演示路径（约 4 分钟）

### A. 昨夜已发生的争抢（开箱即看）

1. 打开**夜间应急退热贴 i13**（大厅余量 0 的那张卡）：可见 5 户家长昨夜同时申请，张晨（儿童 39.4℃、150 米、代送）评分最高已分到并配送中；
   李梅、杨光、赵桂兰、周文未分到，求助记录分别为“相邻小区互助 / 替代用品 / 就医提示已关闭 / 备货待补发”，下方有分配理由全文。
2. 切**李梅（u_e）→ 我的借用**：看到未分到提示与已选的相邻小区出路，提交一条质疑。
3. 切**赵磊（社区工作人员）**：在“分配理由与质疑”按逐项因子答复李梅；在“夜间短缺复盘”看按物品聚合的真实缺口。
4. 切**陈芳（志愿者）→ 到货补发**：看到周文等挂起的求助；点“登记该物品到货”加 3 盒，再“锁定补发”；回到周文的“我的借用”可见已进入交接流程。

### B. 现场制造一次新争抢

1. 切**张晨（u_d）**打开 i1「医用退热贴」（总量 2、已锁定 1，仅剩 1 盒），填紧急程度=儿童高热、有儿童 3 岁、39.5℃、150 米、志愿者代送后提交；
2. 再切**李梅（u_e）**填“发烧/有儿童/300 米/自取”提交；切**周文（u_h）**填“备货/1800 米/自取”提交；
3. 切**陈芳（志愿者）→ 候补协调**：顶部出现“3 户争抢 1 盒”卡片，可先在物品页看实时评分建议，再点“按分配建议执行”；
4. 分别切回三位居民观察“分到并待交接”与“未分到但求助记录保留 + 三条出路 + 质疑入口”的差异。

### C. 原有流程（仍可演示）

审核临期碘伏、口罩配送报备延误、底部时钟 +1 天看超时未取与过期报废、补充新品后候补递补、包装破损/疑似不适隔离与复核。

# 邻里药箱 · 社区共享借用 / 夜间多人申请分配 / 效期提醒 / 邻里互助（演示）

一个纯前端演示应用：居民登记家中多余但**未拆封**的常备非处方耗材（退热贴、碘伏、纱布、创可贴、口罩、体温计电池等），
经社区志愿者审核发布后，邻居可按症状场景申请借用，支持自取 / 志愿者代送 / 邻居门口无接触交接，交接拍照确认，
并按约定归还或补充。效期临近、多人争抢、超时未取、配送延误、共享人撤回、包装破损与疑似不适反应均有对应处理流程。

**本次新增：夜间多户同时申请同一盒退热贴时的公平分配。**
系统不按“谁先点到”分配，而是按 **距离、紧急程度、家中是否有儿童、库存数量、志愿者夜间配送能力** 综合评分给出分配建议；
未分到的居民不会被简单拒绝，而是 **保留求助记录**，可转相邻小区互助、选择替代用品、收到就医提示，库存到货后志愿者按记录补发；
社区端能看到每次分配的逐项评分与理由以便答复居民质疑，并可按批次复盘夜间短缺的真实需求。

> **社区只做物品流转和风险提醒，不做诊断建议。**
> 处方药、拆封药品、冷链药品、过期/包装破损物品**一律不能进入共享**。共享物品不替代就医。

技术栈：Vue 3（`<script setup>`）+ TypeScript + Pinia + Vue Router + Vite + Vitest。
所有数据保存在浏览器 `localStorage`，无后端依赖；底部“演示时钟”可快进，用于演示效期、超时、延误与夜间时段。

## 本地启动

### 方式一：Docker 一键启动（推荐）

```bash
docker compose up -d --build   # 构建并后台启动
# 打开 http://localhost:8080
docker compose down            # 停止
```

多阶段镜像（`Dockerfile`）：Node 20 内完成类型检查与生产构建 → nginx 1.27 托管 `dist/` 静态文件（含 SPA 回退、gzip、缓存与安全响应头）。

### 方式二：本地开发

```bash
npm install        # 如本机 npm 缓存权限异常，可加 --cache /tmp/npm-cache
npm run dev        # http://localhost:5173
```

其他命令：

```bash
npm run typecheck  # vue-tsc 严格类型检查
npm run test       # Vitest 单元/流程/冒烟测试（4 个文件、37 个用例）
npm run build      # 类型检查 + 生产构建（输出到 dist/）
npm run preview    # 预览构建产物
```

## 页面与角色视图

- **药箱大厅 `/hall`**：按四个急用场景筛选 + 关键词搜索；仅展示审核通过且在有效期内的物品。
- **物品详情 `/items/:id`**：借用前强制逐项勾选确认 **来源 / 效期 / 包装状态 / 适用限制**；夜间退热场景申请需填写**紧急程度、家中是否有儿童、孩子当前情况**；
  同页展示该物品的借用记录、**🌙 夜间分配批次（逐户评分因子与分配/不分配理由）、🆘 求助记录**、风险反馈与完整时间线。
- **登记共享 `/register`**：实时规则校验，禁入品（处方药/口服注射药、拆封、冷链、过期、≤30 天临期）提交即被拦截。
- **我的共享 `/my-shares`**：登记人物品状态、确认/婉拒申请、发起交接、拍照确认、撤回。
- **我的借用 `/my-borrows`**：候补、取件、拍照确认、超时警告、登记归还/补充/赠予；**夜间未分到的居民在这里看到自己的求助记录、处理进度、质疑入口**。
- **志愿者工作台 `/volunteer`**：审核、配送拍照/报备延误/改派、超时催办与释放、候补递补；
  新增 **「🌙 夜间分配」**（达到门槛的物品一键生成建议、核对评分后执行）与 **「🆘 求助补发」**（转相邻小区互助/改选替代用品/补发就医提示/到货补发闭环）。
- **社区工作台 `/staff`**：风险看板、反馈处置、过期报废、60/30 天效期分级、双重复核、全链路追溯；
  新增 **「分配理由与质疑」**（查看每次分配的逐户评分、一键生成附理由的质疑答复）与 **「🌙 夜间短缺复盘」**（真实申请户数/满足/未满足/去向/运力缺口/紧急家庭缺口与改进建议）。
- **互助边界 `/guide`**：做什么/不做什么、四类禁入、借用前四项确认、流程、夜间评分分配规则与七种异常处理。

## 夜间多人同时申请的分配规则（可在 `src/utils/allocation.ts`、`src/rules.ts` 核验）

- **触发**：夜间 20:00–次日 06:00 内，同一物品 `NIGHT_BATCH_WINDOW_HOURS`（2）小时里 ≥ `NIGHT_BATCH_MIN_APPLICANTS`（2）户候补申请。
- **评分（满分 100）**：紧急程度 40（critical 40 / urgent 26 / normal 10，家属自报、志愿者电话核实，社区不诊断）
  ＋ 家中有儿童 20 ＋ 距离 20（按楼栋夜间步行估算，1200 米以外为 0）
  ＋ 库存数量匹配 10 ＋ 志愿者配送能力 10。
- **排序与运力的关系**：需求排名只由紧急度/儿童/距离/库存决定；**配送能力是硬约束**——分数够但当晚代送名额（`NIGHT_DELIVERY_CAPACITY`=2 单）已满的家庭不会被挤掉，
  而是标记 `capacityBlocked`，建议改自取/门口交接或转相邻小区互助。自取/门口交接不占用代送名额。
- **未分到居民的三条路径（可叠加，求助记录始终保留）**：
  1. **转相邻小区互助**：安康苑（900 米）等互助点的同类在效期库存，志愿者登记协调并扣减对方余量；
  2. **选择替代用品**：如退热贴缺货时改申请本小区在架的“一次性医用冰袋（冷敷）”，自动锁库存生成借用单；
  3. **收到就医提示**：紧急家庭下发“持续高热/精神差/抽搐/呼吸异常请立即就医或拨打 120”提示（提示不等于闭环）。
- **到货补发**：库存到货/释放（含超时未取释放、共享人补充）后，志愿者在「求助补发」按记录一键安排补发并拍照闭环，**居民无需重新申请**。
- **全程留痕可质疑**：每户的各维度得分、依据与分配/不分配理由都写入批次与物品时间线；居民可对结果提质疑，社区工作人员在看板上对照评分答复。
- **复盘真实需求**：按批次统计真实申请户数、本小区满足、未满足（区分库存缺口/运力缺口/紧急家庭未满足）、各去向数量，并给出补库存/增运力/扩大互助的建议。

## 其他关键业务规则（可在 `src/rules.ts` 与 `src/stores/medkit.ts` 核验）

- **库存锁定**：申请初始为“候补”；确认后锁定数量，取消或闭环后释放，候补按申请时间递补。
- **效期**：60 天黄色预警、30 天红色预警、过期大厅自动禁借并进入工作人员“待报废”清单。
- **取件时限**：确认后 24 小时未完成交接标红，可催办后取消释放给候补。
- **配送 SLA**：志愿者代送 6 小时未完成自动标红，可报备原因、工作人员改派兜底。
- **反馈即隔离**：包装破损、疑似不适提交后物品立即隔离，相关申请取消；工作人员核查后报废或重新发布。
